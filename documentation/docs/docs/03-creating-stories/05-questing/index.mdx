# 任务系统

:::danger[任务扩展]
在开始本教程之前,你必须先安装任务扩展。
:::

任何互动叙事游戏都会有任务系统。任务旨在引导玩家完成故事并提供进度感。

在 Typewriter 中,任务纯粹是一个视觉上的补充。虽然创建互动故事并不一定需要任务系统,但它可以有效地引导玩家完成叙事。

## 创建任务

正如你在设置中看到的,Typewriter 不需要任务组件就可以创建互动故事。与大多数将任务作为主要功能的插件不同,在 Typewriter 中,任务只是一个视觉补充 - 一种引导玩家完成故事并提供进度感的方式。

要创建任务,我们首先需要创建一个清单页面。这个页面将包含构成任务的所有条目。

### 任务如何工作

在 Typewriter 中,使用两种类型的条目来创建任务:`任务`条目和`目标`条目。

`任务`条目定义任务的名称。
`目标`条目定义任务的目标。

### 任务条目

`任务`条目用于定义任务。一个任务可以处于以下三种状态之一:
- 未激活: 任务既未激活也未完成。
- 激活: 任务已激活但玩家尚未完成。
- 已完成: 任务已完成。

`任务`条目有三个重要字段:
- `显示名称`: 任务的名称。
- `激活条件`: 任务变为激活状态必须满足的条件。
- `完成条件`: 任务被视为完成必须满足的条件。

任务状态的确定方式如下:
1. 如果满足所有`完成条件`: 任务完成。
2. 如果满足所有`激活条件`: 任务激活。
3. 否则,任务未激活。

### 目标条目

`目标`条目定义了作为任务一部分需要完成的任务。有各种类型的目标,允许 Typewriter 以不同方式显示它们。

虽然任务有三种不同的状态,但目标只有两种:
- 隐藏: 目标对玩家不可见。
- 可见: 目标对玩家可见。

这些状态受`条件`字段和它们的`受众`父条目的影响。

现在,我们只使用`条件`字段来确定目标是否可见。

## 任务追踪

我们已经看到`任务`可以处于3种状态之一。
此外,我们一次可以**追踪**一个任务。
追踪任务用于向玩家显示任务进度。

要了解更多关于任务显示的信息,请查看[显示任务指南](05-displaying_quests.mdx)。
